## 文件保留规则

- 每个版本只保留一份主报告；报告中的证据使用相对链接，便于本地和仓库页面跳转。
- `tests/`：保留可直接阅读的测试日志、结构化 XML、CLI 结果和用例矩阵；这些形式用途不同，不作为重复文件删除。
- `compilation/`：编译结果、编译选项、ASan 运行库及构建问题排查记录。失败记录保留用于说明环境问题，不列为验收通过证据。
- `bench/`：压测原始输出、报告及包含输入/程序校验值与内存采样的 JSON。
- `metadata/`：环境、测试样本校验值、Git 历史及结果汇总。
- 本次删除4个内容为零字节的压测 stderr 文件；所有非空原始证据保留，移动前后 SHA256 相同。曾发布的 v1.1 标签和历史提交不改写。
- v1.2.0 实际验证成功后再创建其证据目录，避免空目录或占位日志被误认为结果。
